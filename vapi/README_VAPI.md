# Демонстраційне підключення Assistant у Vapi

Ця конфігурація призначена для показу директору на синтетичних даних. Не підключайте реальну клінічну лінію чи реальних пацієнтів, доки не підписані потрібні договори й не погоджені запис, обробка та зберігання даних.

## Підготуйте webhook

1. Запустіть PostgreSQL і застосунок за головним README. `/health` має відповідати успішно.
2. Для локального застосунку Vapi потрібен доступний з інтернету HTTPS URL. Використайте staging VPS із HTTPS або тимчасовий tunnel лише для показу. Compose публікує порт застосунку на `127.0.0.1:8000`, його можна передати тунелю; не відкривайте напряму HTTP-порт чи PostgreSQL у публічний інтернет.
3. Задайте у середовищі бекенду випадковий довгий `VAPI_SECRET`. Для тимчасового тунелю використовуйте окремий demo-секрет і відкличте його після показу.

## Створіть Assistant

1. У Vapi Dashboard відкрийте/створіть Assistant. У `model`, `voice` і `transcriber` шаблону замініть `{{...}}` на доступні для вашого акаунта значення. До збереження перевірте підтримку української та актуальну схему полів у документації Vapi й обраного провайдера.
2. Вставте повний текст `prompts/olena_system_prompt.md` у System message. Шлях до файла сам собою Vapi не підключає.
3. Для First message візьміть фразу з `assistant.template.json`. Вона містить повідомлення про запис; для демонстрації — тільки синтетичний виклик, для реальних дзвінків текст і запис потребують погодження клініки та юриста.
4. Створіть Function tool, перенесіть параметри з `tools/submit_booking_request.json`, задай Server URL `https://<доступний-host>/vapi/webhook` та призначте Custom Credential. Секрет у credential має збігатися з `VAPI_SECRET` застосунку.
5. Backend приймає `X-Vapi-Secret` і `Authorization: Bearer ...`. Встановіть у Dashboard той спосіб credential, який підтверджено актуальною документацією Vapi для вашого поля Server URL. Не додавайте секрет до URL.
6. Увімкніть серверні події `tool-calls` та `end-of-call-report`, додайте штатний `endCall`, якщо він доступний у вашій конфігурації. Формат цих полів звірте з актуальною схемою Assistant.
7. Для демо залиште телефонний номер незаданим і проведіть web-call/Dashboard call. У Vapi скажіть асистенту лише синтетичні демонстраційні дані. Успішний шлях: виклик Function tool → рядок у локальній/staging БД → відповідь голосом → текстове повідомлення в групі Telegram → після завершення дзвінка аудіофайл у тій самій групі.

## Підключіть номер пізніше

Безкоштовні номери Vapi наразі мають американські коди та підтримують лише вхідні дзвінки. Для українського номера спершу зверніться до телефонного оператора клініки: попросіть умови SIP trunk/маршрутизації вхідного номера, тариф за хвилину та дані для інтеграції. До купівлі нового номера підтвердьте у Vapi сумісність конкретного провайдера. [Довідка Vapi про телефонію](https://docs.vapi.ai/phone-calling), [SIP trunking](https://docs.vapi.ai/advanced/sip/sip-trunk).

## Після демонстрації

- Зупиніть tunnel або видаліть staging endpoint, якщо він більше не потрібен.
- Відкличте demo `VAPI_SECRET`, якщо URL був тимчасово опублікований, і згенеруйте новий при наступному розгортанні.
- Видаліть синтетичні записи/аудіо відповідно до плану демо. Не завантажуйте реальні аудіо до Telegram.
- Перед запуском для клініки окремо перевірте заголовок credential, поля транскрипту/запису та строк зберігання даних у вашому Vapi акаунті.

## Звірити з Vapi перед збереженням

- актуальні поля Assistant, server URL, `serverMessages`, `artifactPlan`, timeout і endCall;
- credential type і фактичний HTTP-заголовок;
- українську мову обраного LLM, voice та transcriber;
- структуру `artifact.transcript`, посилання/тип аудіозапису та правила зберігання;
- підтримку SIP або номера українського оператора у вашому тарифі/регіоні.

Офіційна документація: [Server URL](https://docs.vapi.ai/server-url), [Server events](https://docs.vapi.ai/server-url/events), [Pricing](https://docs.vapi.ai/billing/pricing-and-success-packages).

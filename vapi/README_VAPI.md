# Підключення Assistant у Vapi до бекенду

Ця інструкція описує ручне налаштування. Шаблони не створюють Assistant автоматично та не містять даних вашого акаунта. Назви полів Dashboard можуть змінюватися — перед збереженням звірте їх з актуальною документацією [Vapi Server URL](https://docs.vapi.ai/server-url) та [Server events](https://docs.vapi.ai/server-url/events).

## Передумови

1. Закрийте юридичні й безпекові блокери з головного README. Не використовуйте реальних дзвінків до формального дозволу клініки та погодження обробки/запису.
2. Розгорніть застосунок і PostgreSQL у контрольованому середовищі. Застосунок має бути доступний за HTTPS, наприклад `https://<ваш-домен>`, і `https://<ваш-домен>/health` має відповідати успішно.
3. У змінних середовища бекенду встановіть довгий випадковий `VAPI_SECRET`. В Dashboard Vapi створіть відповідний Custom Credential із тим самим значенням. Не зберігайте credential у JSON-шаблоні чи Git.

## Налаштування Assistant

1. У Vapi Dashboard створіть Assistant. Поля моделі, голосу й транскрайбера беріть із `assistant.template.json` лише як перелік необхідних налаштувань. Оберіть провайдери та перевірте підтримку української й актуальну схему полів у документації Vapi/провайдера; шаблонні `{{...}}` значення не є конфігурацією для збереження.
2. Відкрийте `../prompts/olena_system_prompt.md`, скопіюйте його повний текст і вставте у System message / системні інструкції Assistant. Файловий шлях сам собою Vapi не підключає.
3. Вкажіть перше повідомлення (First message) із шаблону. Його фраза «Розмова записується» — технічний заповнювач: юрист клініки має погодити текст і момент повідомлення до активації запису.
4. Створіть Function tool, перенесіть визначення з `tools/submit_booking_request.json` і встановіть його Server URL: `https://<ваш-домен>/vapi/webhook`. У серверних налаштуваннях Assistant увімкніть повідомлення `tool-calls` та `end-of-call-report`, якщо актуальна схема Dashboard їх підтримує.
5. Додайте Vapi Custom Credential для server URL і призначте його інструменту/Assistant відповідно до Dashboard. Backend приймає `X-Vapi-Secret` та `Authorization: Bearer ...`; який заголовок Vapi надсилає з обраним видом credential — перевірте в актуальній документації й фактичним контрольованим запитом. Не передавайте секрет у URL.
6. Додайте штатний `endCall` до інструментів Assistant, якщо це передбачено поточною схемою Vapi. Перевірте, що системні інструкції викликають завершення після фінальної репліки та після екстреної інструкції.
7. Встановіть розумне обмеження тривалості й тиші. Запис і транскрипцію вмикайте лише після погодження правових підстав, тексту повідомлення, доступу до артефактів і строку видалення. Поля `artifactPlan`, `serverMessages`, параметри таймауту та `endCall` звірте з актуальною схемою у Vapi Dashboard.
8. Збережіть Assistant і призначте йому телефонний номер/канал відповідно до способу роботи вашої клініки. Цей крок залежить від обраного тарифу, номера й конфігурації акаунта; звірте з документацією Vapi, не припускайте, що шаблон створює телефонію.

## Контроль введення в експлуатацію

- Перевірте, що Vapi дістається лише HTTPS webhook, неправильний секрет відхиляється, правильний дозволяє запит.
- Перевірте у захищеному середовищі з погодженими синтетичними даними весь ланцюг: Function tool → запис заявки у PostgreSQL → відповідь інструмента → Telegram-сповіщення за наявності налаштованих адміністраторів → журнал завершення дзвінка.
- Переконайтеся, що логи не містять номерів, імен, скарг, транскриптів чи секретів; перевірте права доступу та строки зберігання в базі, Vapi й Telegram.
- Не використовуйте тимчасовий тунель як production. Якщо тунель потрібен для попередньо погодженого технічного тесту, він робить ваш webhook доступним з інтернету: обмежте час, використовуйте окремий тимчасовий секрет і синтетичний payload, вимкніть тунель та відкличте секрет після тесту.

## Потрібно звірити з Vapi

- актуальні поля Assistant, інструмента, server URL і призначення Custom Credential;
- який заголовок і формат авторизації надсилаються для credential, створеного у вашому акаунті;
- підтримку української для фактично обраних моделі, голосу й транскрайбера;
- точні поля подій, транскрипту, запису, таймаутів та endCall;
- доступність телефонного номера/каналу, записів і керування згодою у вашому тарифі/акаунті.

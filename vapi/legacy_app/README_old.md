# Verika — демонстраційний бекенд голосового асистента

Проєкт приймає дзвінок через Vapi, зберігає заявку/звіт у PostgreSQL і надсилає адміністраторам текстові сповіщення в Telegram. Пересилання аудіозаписів вимкнене за замовчуванням. Поточний стан придатний для локальної технічної демонстрації на синтетичних даних. Не підключайте реальних пацієнтів, клінічний номер або реальні медичні відомості до оформлення договорів, згоди, правил зберігання та захищеного production-середовища.

## Потік даних

1. Vapi надсилає `tool-calls` у `POST /vapi/webhook`.
2. `app.main` перевіряє Bearer або `X-Vapi-Secret` і читає `toolCallList[].function`.
3. `app.schemas` перевіряє всі поля заявки, дозволений каталог послуг і український номер; `app.transcripts` виділяє репліки пацієнта для журналу дзвінка.
4. `app.db` зберігає заявку з ідемпотентним ключем `call_id:tool_call_id`.
5. `app.notifier` надсилає адміну текст; аудіо пересилається лише при явному ввімкненні окремої опції.
6. Vapi надсилає `end-of-call-report`; бекенд зберігає транскрипт і стан передзвону. Для аудіо бекенд за `call_id` звертається до приватного Vapi API та не зберігає короткоживучий signed URL.
7. Відповідь Function tool повертається Vapi як один рядок у `results[].result`; помилка — у `results[].error`.


## Які дані потрапляють у заявку

Після усного підтвердження Олена передає в `submit_booking_request` ім'я, телефон, обрану послугу, місто, дату (зараз завжди «Не вказано»), побажання щодо половини дня та короткий підсумок запиту. Backend перевіряє значення й записує ці поля в `booking_requests`; Telegram-сповіщення для адміністраторів бере дані з цього рядка. Окремий `end-of-call-report` зберігає транскрипт і стан передзвону, а не замінює заявку.

## Локальний запуск

Потрібні Python 3.12+ або Docker Compose. Для найпростішої демонстрації не купуйте телефонний номер чи VPS: запустіть backend локально, а Assistant перевіряйте через Vapi web-call. Щоб Vapi дістався локального webhook, потрібен тимчасовий HTTPS tunnel або staging URL.

### Варіант A: Docker Compose

У PowerShell з кореня проєкту:

```powershell
Copy-Item .env.example .env
```

Відредагуйте `.env`: задайте довгий випадковий `VAPI_SECRET` і простий URL-безпечний пароль `POSTGRES_PASSWORD` (лише латинські літери/цифри для локального Compose). `TG_BOT_TOKEN` та `TG_ADMIN_IDS` залиште порожніми, якщо Telegram ще не готовий. `FORWARD_RECORDINGS_TO_TELEGRAM` залиште `false`; `VAPI_PRIVATE_API_KEY` не потрібен для звичайного запуску. Не вставляйте Private API key у `VAPI_SECRET`.

Запуск і перевірка:

```powershell
docker compose up --build
Invoke-RestMethod http://localhost:8000/health
```

Очікується `ok: true`; міграції запускаються під час старту. Зупиніть `Ctrl+C`. `docker compose down` зберігає локальну базу у volume; `docker compose down -v` видаляє її разом із демонстраційними даними.

### Варіант B: Python та локальний PostgreSQL

1. Встановіть і запустіть PostgreSQL локально. Через `psql -U postgres` або pgAdmin створіть окремого користувача й базу:

   ```sql
   CREATE USER booking WITH PASSWORD '<ваш_власний_пароль_з_літер_і_цифр>';
   CREATE DATABASE booking OWNER booking;
   ```

2. Скопіюйте `.env.example` у `.env` та вкажіть `DATABASE_URL=postgresql://booking:<той_самий_пароль>@localhost:5432/booking`. Для простоти локального старту візьміть пароль лише з латинських літер і цифр; інакше спеціальні символи у URI потрібно URL-кодувати.
3. З кореня репозиторію виконайте:

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
   ```

4. Перевірте `http://127.0.0.1:8000/health`.

У локальному Python запуску `.env` має містити адресу `localhost`; у Compose її задає сервіс `app` як `db:5432`. Telegram необов'язковий: якщо немає токена або chat ID, сповіщення не запускаються, заявки лишаються у БД.

## Налаштування Telegram-групи адміністраторів

1. У `@BotFather` створіть бота через `/newbot`; його токен збережіть у менеджері паролів. Якщо токен потрапив у скриншот чи чат, відкличте його через BotFather та замініть у `.env`.
2. Створіть приватну групу адміністраторів і додайте бота як учасника. Для надсилання ботом повідомлень права адміністратора зазвичай не потрібні.
3. Напишіть у групі команду `/start@<username_бота>`, щоб у Telegram з'явився update для цього бота. Якщо в боті вже налаштований Telegram webhook, `getUpdates` не працюватиме, доки той webhook не буде прибраний.
4. У корені проєкту запустіть `python scripts/get_telegram_chat_id.py`. Скрипт читає токен з локального `.env` і друкує тільки числові chat ID. Для групи ID зазвичай від'ємний і може починатися з `-100`. Не відкривайте URL із токеном у браузері й не копіюйте сирий Telegram update у чат.
5. Запишіть локально у `.env`:

   ```dotenv
   TG_BOT_TOKEN=<токен цього Telegram-бота>
   TG_ADMIN_IDS=<числовий ID приватної групи>
   ```

6. Перезапустіть застосунок. Перевірте доставку тільки після окремого demo-виклику з вигаданими даними.

Можна вказати кілька ID через кому; успіхом вважається доставка хоча б в один заданий чат. Telegram не є сховищем для аудіозаписів пацієнтів: доступ і строки видалення мають бути окремо погоджені до реального використання.

## Ручне підключення Vapi

Поточний код підтримує Vapi Function payload `message.toolCallList[].function.name` і `.arguments`, а також формат відповіді `results[]` із рядковим `result` або `error`. [Офіційний контракт Function tool](https://docs.vapi.ai/tools/custom-tools), [формат `end-of-call-report`](https://docs.vapi.ai/server-url/events).

1. Запустіть backend і перевірте `/health`.
2. Надайте Vapi тимчасовий публічний HTTPS URL на час тесту. Наприклад, tunnel може проксувати локальний `127.0.0.1:8000`; вимкніть його відразу після демо. Не відкривайте публічно PostgreSQL чи звичайний HTTP порт 8000.
3. У Vapi створіть **Custom Credential → Bearer Token**. Задайте токен, який точно збігається з `VAPI_SECRET` у backend. Рекомендовано `Authorization` + увімкнений префікс `Bearer`. Альтернатива — назва заголовка `X-Vapi-Secret` без префікса `Bearer`. Backend підтримує обидва способи. Це має бути окремий випадковий webhook-секрет, **не Private API key акаунта Vapi**. [Офіційні типи credential і заголовки](https://docs.vapi.ai/server-url/server-authentication).
4. Створіть Function tool `submit_booking_request` і перенесіть поля з `vapi/tools/submit_booking_request.json`. У Server Settings задайте `https://<публічний-host>/vapi/webhook` та створений credential.
5. У налаштуваннях збереженого Assistant задайте такий самий Server URL/credential для серверних подій і ввімкніть `tool-calls` та `end-of-call-report`. Для URL, заданого безпосередньо в тимчасовому API-запиті до Vapi, credentials можуть не прикріпитися; використовуйте збережений Assistant/Tool у Dashboard. [Пріоритет server URL](https://docs.vapi.ai/server-url/setting-server-urls).
6. Вставте текст `prompts/olena_system_prompt.md` у системне поле Assistant. Шлях до файла Vapi не читає.
7. У First Message скопіюйте вступ із `vapi/assistant.template.json`. Фраза про запис зараз є технічним заповнювачем; її юридичне формулювання має погодити юрист перед реальними дзвінками.
8. Додайте штатний `endCall`, виберіть модель, голос і транскрайбер, у яких окремо перевірили підтримку української. Увімкніть запис і транскрипт тільки для синтетичної демонстрації.
9. У повідомленні інструмента `Request Failed` задайте точну фразу: «Вибачте, сталася технічна помилка. Будь ласка, зателефонуйте нам зранку.» Backend для помилки повертає поле `error`; Vapi за документацією запускає налаштоване повідомлення `Request Failed`, а не озвучує текст із поля `error` автоматично. [Обробка помилки інструмента](https://docs.vapi.ai/tools/custom-tools).
10. Проведіть web-call із вигаданими даними. У Vapi Logs перевірте виклик інструмента та аргументи; у PostgreSQL — один рядок заявки; у приватній тестовій Telegram-групі — повідомлення. Перевірте фінальний транскрипт і завершення дзвінка.

### Пересилання записів

Запис не надсилається в Telegram, доки `FORWARD_RECORDINGS_TO_TELEGRAM=false`. Для синтетичної демонстрації, якщо команді справді потрібно переслати аудіо, у backend `.env` задайте окремий `VAPI_PRIVATE_API_KEY` (Private API key акаунта Vapi) і `FORWARD_RECORDINGS_TO_TELEGRAM=true`. Це **не** `VAPI_SECRET`: останній лише автентифікує webhook.

Vapi зберігає записи у приватному сховищі. Backend робить `GET https://api.vapi.ai/call/{call_id}/mono-recording` з `Authorization: Bearer <VAPI_PRIVATE_API_KEY>`, отримує redirect на короткоживучий signed URL і пересилає bearer тільки до `api.vapi.ai`. Redirect приймається лише для HTTPS hostname, явно зазначеного у `VAPI_RECORDING_HOSTS`; цей список заповнюйте лише після перегляду домену redirect без копіювання URL чи query string. Backend обмежує файл 45 MiB і не записує signed URL у базу чи лог.

Важливо: цей перемикач контролює лише пересилання аудіо з backend до Telegram. Якщо запис увімкнений у Vapi Assistant (`artifactPlan.recordingEnabled`), Vapi усе одно зберігає його у своєму сховищі; це окрема настройка Assistant. Не вмикайте запис/пересилання для реальних дзвінків без погоджених згоди, договорів, доступів і строків зберігання.

## Номер і провайдер телефонії

Для першої демонстрації директору номер не потрібен: проведіть web-call у Vapi. Безкоштовний номер Vapi — американський і підтримує тільки вхідні дзвінки; для українського номера або вихідних дзвінків треба імпортувати сумісний номер/телефонний маршрут. [Довідка Vapi про номери](https://docs.vapi.ai/phone-calling).

Для майбутнього підключення клініки спочатку запитайте її поточного телефонного оператора, чи надає він SIP trunk/переадресацію в Vapi, і отримайте письмову ціну за номер, хвилину, підключення та документи. Telnyx є кандидатом: Vapi документує інтеграцію, але попереджає про можливе спотворення аудіо на деяких міжнародних дзвінках через різницю PCMA/PCMU. Telnyx вказує для українських DID перевірку бізнесу та адреси й орієнтовно 72 години на перевірку документів. Тому не купуйте номер до підтвердження доступності, остаточної ціни й короткого тесту якості з Vapi. [Vapi + Telnyx](https://docs.vapi.ai/telnyx), [вимоги Telnyx для України](https://support-v2.telnyx.com/en/articles/3739745-ukraine-did-requirements).

## Рішення

- Агент збирає заявки й допомагає обрати послугу з затвердженого списку; він не оцінює стан і не замінює рішення медичного працівника. До реальних дзвінків клініка має затвердити каталог послуг і правила направлення.
- Коли людина не знає послуги, агент пропонує консультацію флеболога лише для явно згаданих питань про видимі вени, судинні зірочки, важкість або набряк ніг; консультацію проктолога — лише за прямим запитом до проктолога. Для інших або неясних запитів пропонується передзвін. Процедури й обстеження за скаргами не підбираються. Це безпечне обмеження, а клініка має затвердити каталог і мапу направлення до демонстрації.
- Поля дати, бажаної половини дня та короткого підсумку обов’язково мають бути присутні у виклику інструмента. Якщо дату чи побажання не названо, передається «Не вказано»; фактичний час адміністратор узгоджує пізніше.
- Якщо телефон відсутній, він порожній лише для `Передзвін`; в інших випадках схема просить номер. Синтаксично валідні типові українські формати нормалізуються до `+380…`.
- Сповіщення доставляються за принципом щонайменше однієї спроби. Після падіння між HTTP-відправкою й записом результату можлива повторна доставка; idempotency захищає створення заявки, але Telegram не надає транзакційної exactly-once доставки.
- Пересилання записів у Telegram вимкнене за замовчуванням. Якщо його окремо ввімкнути для демо, backend отримує recording через автентифікований Vapi API; signed URL не зберігається, а домен redirect має бути в точному HTTPS allowlist.
- Секрети з попередніх скриншотів вважайте розкритими. Відкличте Telegram Bot token і Vapi Private API key у відповідних кабінетах; окремо створіть новий випадковий `VAPI_SECRET`. Не переносіть Private API key до `VAPI_SECRET`.
- Docker/Compose конфігурація — тільки локальна демонстраційна, без публічного TLS, резервного копіювання, моніторингу чи автоматичної ротації секретів.

## Не готово до реальних даних

Перед реальними дзвінками клініка й команда мають завершити та письмово погодити:

- договори з клінікою, Vapi, телефонним провайдером і всіма обробниками даних;
- правову підставу та узгоджене повідомлення/згоду на запис і обробку даних;
- політику зберігання та автоматичного видалення транскриптів, заявок і записів у PostgreSQL, Vapi й Telegram;
- production-хостинг, TLS, мережеві правила, резервні копії та перевірене відновлення БД;
- моніторинг помилок/черг без запису ПІБ, номерів, скарг, секретів і signed URL;
- ротацію секретів, контроль доступу до Telegram-групи та рішення, чи допустимо надсилати туди записи;
- затвердження клінікою каталогу послуг, правил рекомендації консультацій і маршруту передзвону;
- перевірку якості розпізнавання/синтезу української та погоджений сценарій передачі звернення адміністратору;
- юридичну оцінку First Message про запис і вимог до медичних/персональних даних.

## Поточні межі перевірки

У цій копії немає вихідних pytest-тестів і демо-фікстур; автоматизований тестовий набір не додавався, бо попередня вимога була прибрати тести й приклади. Міграції потребують перевірки на окремій локальній БД. Docker Compose-конфіг можна перевірити без запуску контейнерів, але працездатність локального Docker daemon із цього середовища не підтверджена. Зміни тут не підключаються до Vapi, Telegram чи робочої БД автоматично.

Залишилися ручні перевірки `TODO(verify-vapi)`: доступність української у вибраних model/voice/transcriber для вашого акаунта та hostname redirect від `GET /call/{id}/mono-recording` у першому синтетичному дзвінку, якщо потрібне пересилання аудіо. До перевірки redirect залишайте `VAPI_RECORDING_HOSTS` порожнім, а пересилання вимкненим.

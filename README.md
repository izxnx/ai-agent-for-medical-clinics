# Verika — бекенд голосового асистента клініки

Цей репозиторій готує бекенд для підключення голосового асистента Олени у Vapi. **Зараз його не можна використовувати для дзвінків реальних пацієнтів.** У клініки ще немає потрібних угод і налаштованого production-сервера; у цьому репозиторії немає ваших секретів, домену чи облікових даних Vapi.

## Як працює система

Vapi приймає дзвінок і надсилає подію `tool-calls` або `end-of-call-report` на `https://<ваш-домен>/vapi/webhook`. FastAPI перевіряє секрет, валідовує заявку, визначає можливі ознаки терміновості, зберігає заявку/журнал у PostgreSQL та ставить сповіщення Telegram у чергу повторних спроб. Відповідь інструмента повертається асистенту, який озвучує її пацієнту. Звіт про завершення дзвінка зберігає транскрипт і посилання на запис; за наявності незавершеної заявки або ознак ризику адміністратори отримують повідомлення.

Детектор ознак ризику — лише друга лінія захисту поверх рішення мовної моделі, а не заміна клінічного тріажу.

## Що потрібно підготувати і куди вставляти

1. **Юридичний дозвіл і домовленості:** до обробки реальних дзвінків укладіть потрібні договори з клінікою та постачальниками, визначте ролі сторін, мету/підставу обробки, повідомлення пацієнту, згоду на запис, строки зберігання/видалення та порядок реагування на інциденти. Юрист має погодити текст повідомлення про запис.
2. **Сервер і база:** оберіть контрольований хостинг у прийнятній юрисдикції, домен із HTTPS та PostgreSQL із резервними копіями, обмеженим доступом і планом відновлення. Після розгортання публічна адреса має бути `https://<ваш-домен>`; її вставте у Vapi замість `{{SERVER_URL}}`. Не відкривайте PostgreSQL в інтернет.
3. **Секрети:** скопіюйте `.env.example` у `.env`. Встановіть випадковий довгий `VAPI_SECRET`, а `DATABASE_URL` — на вашу базу. `POSTGRES_PASSWORD` потрібен для локального Compose; у production використовуйте секрети середовища вашого хостингу. Не вставляйте реальні значення у цей README, JSON-шаблони, Git чи листування.
4. **Telegram:** за потреби створіть бота через офіційний BotFather, внесіть токен у `TG_BOT_TOKEN`, а дозволені chat ID адміністраторів — у `TG_ADMIN_IDS` через кому. Адміністратори мають самі почати чат із ботом. Без цих двох значень Telegram-сповіщення вимкнені, заявки все одно зберігаються в PostgreSQL. Не надсилайте записи до Telegram, поки не погоджені доступ і правова підстава.
5. **Vapi:** створіть Assistant і Function tool за інструкцією [`vapi/README_VAPI.md`](vapi/README_VAPI.md). У Dashboard налаштуйте URL webhook і credential із тим самим секретом, що `VAPI_SECRET`; реальний URL/секрет у репозиторій не записуйте.
6. **Перевірка перед запуском:** спершу перевірте міграції, `/health`, права доступу, журналювання без персональних даних, Telegram-доставку, повторні події та відновлення з резервної копії у контрольованому середовищі. Потім проведіть погоджений внутрішній тест із синтетичними даними. Лише після формального дозволу переходьте до реальних дзвінків.

## Локальний запуск

Потрібен Python 3.12 або Docker із Compose. Скопіюйте `.env.example` у `.env` і змініть `POSTGRES_PASSWORD` та `VAPI_SECRET` на власні випадкові значення.

**Docker Compose** (локальний застосунок і база):

```powershell
Copy-Item .env.example .env
docker compose up --build
```

Перевірка локального health endpoint: `http://localhost:8000/health`. Зупинка: `Ctrl+C`, потім `docker compose down`. Базу зберігає volume `postgres_data`; видаляйте його лише якщо свідомо хочете знищити локальні дані.

**Python і вже встановлений локальний PostgreSQL:** у `.env` вкажіть адресу доступної локальної бази, наприклад `postgresql://<користувач>:<пароль>@localhost:5432/<база>`, встановіть залежності `python -m pip install -r requirements.txt`, запустіть `uvicorn app.main:app --host 127.0.0.1 --port 8000`. Під час старту застосунок створює/оновлює схему міграціями. Для прийому webhook із Vapi потрібен публічно доступний HTTPS endpoint; `localhost` Vapi не бачить.

## Рішення

- Для звичайної заявки телефон обов'язковий; порожній дозволений для термінового звернення або послуги «Передзвін». Типові українські формати нормалізуються до `+380XXXXXXXXX`.
- Детектор термінових ознак має ухил на повноту: може позначити неоднозначну фразу як пріоритетну. Адміністрація клініки має визначити безпечний процес реагування; це не медичний тріаж.
- Для транскрипту передбачено рядки `User:`/`Customer:` і fallback на повний текст. Фактичне представлення транскрипту й запису залежить від подій/налаштувань Vapi та має бути перевірене в обліковому записі клініки.
- Запис розмови ввімкнено у шаблоні Vapi як налаштування для розгляду; не активуйте його на реальних дзвінках до юридичного погодження. Фраза про запис у `firstMessage` — технічний заповнювач, формулювання погоджує юрист.
- Сповіщення Telegram передають персональну інформацію, якщо їх увімкнути. Потрібно окремо погодити доступ, мінімізацію, зберігання та використання цього каналу.

## Не готово до реальних даних

Наразі немає підписаних договорів/угод із клінікою та обробниками, юридично погодженого повідомлення і згоди на запис, затверджених строків зберігання та процедури видалення, production-сервера/домену/HTTPS, захищеної production-бази й резервного відновлення, моніторингу та плану реагування, ротації секретів, перевіреного обмеження доступу до записів у Telegram, юридичної оцінки, реальних Vapi credential/model/voice/transcriber та приймального тестування в цільовому акаунті. Це обов'язкові блокери до ввімкнення реальних дзвінків.

# Verika — демонстраційний голосовий асистент для клініки

**Поточна мета — показати директору клініки технічний сценарій на вигаданих даних. Не підключайте реальні дзвінки, номери пацієнтів чи записи.** Угоду з клінікою та обробниками даних ще не оформлено; production-хостинг і телефонний маршрут не налаштовані. Перед реальною експлуатацією потрібні окреме погодження, договори, політики доступу/зберігання та production-перевірка.

## Що показує демонстрація

Vapi Assistant веде голосову розмову та після збору заявки викликає єдиний Function tool. HTTPS webhook у `app/main.py` перевіряє секрет, `app/schemas.py` перевіряє заявку, `app/urgency.py` позначає можливі термінові ознаки, `app/db.py` зберігає дані у PostgreSQL. Після дзвінка Vapi надсилає звіт; застосунок записує журнал, завантажує аудіофайл і надсилає його в задану Telegram-групу адміністраторів. Відповідь інструмента повертається Vapi для озвучення.

Для показу підготуйте лише синтетичні дані: демонстраційне ім'я, номер формату `+380000000000`, вигадану скаргу. Терміновість у коді — евристична друга лінія захисту, не клінічний тріаж і не підтверджена медична оцінка.

## Демонстраційний запуск локально

Потрібен Python 3.12 або Docker із Compose. Створіть локальні секрети:

```powershell
Copy-Item .env.example .env
```

Відкрийте `.env` і змініть `POSTGRES_PASSWORD` та `VAPI_SECRET`. Для Compose пароль БД має бути URL-безпечним (латинські літери й цифри). `TG_BOT_TOKEN` та `TG_ADMIN_IDS` можна залишити порожніми, доки не створите групу.

Запустіть локальне demo-середовище:

```powershell
docker compose up --build
```

Перевірте `http://localhost:8000/health`; очікувана відповідь — `{"ok":true}`. Міграції застосовуються автоматично. Зупинка — `Ctrl+C`, потім `docker compose down`. Дані демо лишаються в локальному volume `postgres_data`; це не production-база.

**Щоб Vapi викликав ваш локальний webhook**, `localhost` недостатньо: Vapi працює ззовні. Для демонстрації використайте тимчасовий HTTPS tunnel або staging URL. Tunnel відкриває endpoint в інтернет, тому обмежте час роботи, використовуйте окремий випадковий `VAPI_SECRET`, не надсилайте реальні дані й вимкніть його відразу після показу. Для постійного URL потрібні сервер, домен і HTTPS reverse proxy/хостинг із TLS. Звичайний порт `8000` у Compose — локальний HTTP, його не можна виставляти як production webhook.

Якщо запускаєте без Docker, потрібен встановлений PostgreSQL. У `.env` задайте `DATABASE_URL=postgresql://<користувач>:<пароль>@localhost:5432/<база>`, встановіть `python -m pip install -r requirements.txt`, потім запустіть `uvicorn app.main:app --host 127.0.0.1 --port 8000`.

## Підключення Telegram-групи

1. У `@BotFather` виконайте `/newbot` і збережіть токен у секретному місці. Не надсилайте його в загальний чат команди й не комітьте в Git.
2. Створіть приватну Telegram-групу для демонстрації, додайте бота та дозвольте йому надсилати повідомлення. Для відправлення бот не мусить читати групу.
3. У групі надішліть нешкідливу команду `/start@<username_бота>`. Розробник отримує Telegram update через безпечний локальний спосіб і копіює тільки `message.chat.id`. Не вставляйте токен у скриншоти/README та не зберігайте повну відповідь із `getUpdates`.
4. Внесіть у `.env`:

   ```dotenv
   TG_BOT_TOKEN=<токен від BotFather>
   TG_ADMIN_IDS=<ID вашої групи, зазвичай -100...>
   ```

5. Перезапустіть застосунок і перевірте нешкідливе службове повідомлення. Якщо вкажете кілька chat ID через кому, застосунок надсилатиме в кожен; для спільної групи достатньо одного ID.

Бот і Telegram для цього сценарію окремо купувати не потрібно. Група має бути закритою; переслані туди аудіозаписи стають копіями у Telegram, і доступ до них треба погодити окремо.

## Підключення Vapi

Повна інструкція — у [`vapi/README_VAPI.md`](vapi/README_VAPI.md). Коротко: застосунок має бути доступний з інтернету за HTTPS; вставте URL `https://<ваш-домен>/vapi/webhook` у server URL Function tool, створіть Vapi Custom Credential зі значенням `VAPI_SECRET`, вставте системний промт вручну, додайте Function tool та штатний `endCall`, увімкніть події `tool-calls` і `end-of-call-report`. Поля шаблону, українську мову, тип credential і заголовок звірте з вашим актуальним Dashboard Vapi.

Для демонстрації використовуйте Vapi web-call/Dashboard із синтетичною заявкою; телефонний номер клініки зараз не потрібен. Для звичайного дзвінка з телефонної мережі спершу узгодьте з оператором клініки SIP trunk/маршрутизацію на Vapi.

## Що купити для демо, що відкласти

Ціни перевірені **14.10.2026**; остаточну суму дивіться у вашому акаунті й у кошику провайдера.

### Щоб показати демо в найближчі дні

- **Vapi:** акаунт у вас уже є. На Usage-only актуальна сторінка показує $0 за пакет і далі $0.05 за хвилину Vapi hosting плюс витрати на модель, голос, транскрайбер і телефонію. Сторінка наводить приклад близько $82–$129 за 1,000 хвилин з конкретними провайдерами; це лише орієнтир, не рахунок для вашої конфігурації. Спершу перевірте наявний баланс/тарифи; Core за $29/місяць не обов'язковий для базової демонстрації. [Тарифи Vapi](https://vapi.ai/pricing), [деталі білінгу](https://docs.vapi.ai/billing/pricing-and-success-packages).
- **Hosting:** якщо директор дивиться демо через screen-share і локальний tunnel достатній — окремий сервер можна не купувати. Якщо потрібна стабільна публічна demo-адреса, візьміть невеликий VPS у прийнятному регіоні. Поточний приклад Hetzner CX23 у Німеччині/Фінляндії — €5.49/місяць без VAT, плюс €0.50/місяць за IPv4; це лише синтетичне staging, не оцінка готовності до даних пацієнтів. [Актуальні ціни Hetzner](https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/).
- **Domain:** купуйте лише якщо немає домену клініки/проєкту і потрібен постійний staging URL. Ціна залежить від доменної зони та реєстратора. Для короткого demo URL можна надати HTTPS tunnel, але не залишайте його ввімкненим.
- **Telegram:** безкоштовно. Створіть приватну групу й бота; платний Telegram-сервіс не потрібен.
- **SSL/TLS:** окрема покупка зазвичай не потрібна, якщо ваш reverse proxy/хостинг видає сертифікат автоматично. Для Vapi публічний webhook має бути HTTPS.
- **Телефонія:** для web-call не купуйте номер. Безкоштовний номер Vapi, за їхньою документацією, американський і лише для вхідних дзвінків. Для українського номера спочатку поговоріть з поточним телефонним оператором клініки про SIP trunk і ціну; новий номер/провайдера купуйте тільки після підтвердження сумісності у Vapi. [Телефонія Vapi](https://docs.vapi.ai/phone-calling).

### Відкласти до рішення про реальне використання

Production-сервер із відповідним договором обробки даних, окрема керована PostgreSQL-база, резервні копії/відновлення, моніторинг, об'єктне сховище записів і телефонний маршрут закуповуються після вибору клінікою політики даних, регіону та строку зберігання. Не купуйте найдешевший VPS як заміну цим вимогам. Vapi згадує окрему HIPAA-опцію, але HIPAA — право США; не купуйте її автоматично для української клініки без поради юриста. [Vapi про HIPAA та BAA](https://docs.vapi.ai/security-and-privacy/hipaa).

## Відомі технічні межі demo

- У репозиторії зараз немає тестового набору: його видалили на попередній ітерації. Перед production команда має відновити автоматизовані перевірки з повністю синтетичними даними.
- Слід підтвердити у Vapi payload `call.customer.number`, структуру запису/транскрипту й назву header для обраного Custom Credential.
- Telegram-повідомлення/запис повторюються після помилки. HTTP I/O для Telegram виконується під час транзакції БД; запис може тримати її до 60 секунд завантаження плюс до 60 секунд відправлення. Це прийнятно для малої демонстрації, але треба переробити до production.
- Немає договорів, формального погодження запису, строків зберігання/видалення, production-хостингу, моніторингу та затвердженого доступу до Telegram. До їх вирішення — лише синтетичні демонстрації.

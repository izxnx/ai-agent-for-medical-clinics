# Verika — демонстраційний бекенд голосового асистента

Проєкт приймає дзвінок через Retell AI, зберігає заявку/звіт у PostgreSQL і надсилає адміністраторам текстові сповіщення в Telegram. Пересилання аудіозаписів вимкнене за замовчуванням. Поточний стан придатний для локальної технічної демонстрації на синтетичних даних. Не підключайте реальних пацієнтів, клінічний номер або реальні медичні відомості до оформлення договорів, згоди, правил зберігання та захищеного production-середовища.

## Потік даних

1. Під час дзвінка Retell викликає custom function: `POST /retell/function` з тілом `{"name", "call", "args"}`.
2. `app.main` перевіряє підпис `X-Retell-Signature` (HMAC-SHA256 сирого тіла + timestamp, ключ — `RETELL_API_KEY`) і передає `args` у потрібний tool за `name`.
3. `app.schemas` перевіряє всі поля заявки, дозволений каталог послуг і український номер; `app.transcripts` виділяє репліки пацієнта для журналу дзвінка.
4. `app.db` зберігає заявку з ідемпотентним ключем `call_id:sha256(нормалізовані поля)` (Retell не передає tool_call_id).
5. `app.notifier` надсилає адміну текст; аудіо пересилається лише при явному ввімкненні окремої опції.
6. Після дзвінка Retell надсилає подію `call_ended` у `POST /retell/webhook`; бекенд зберігає транскрипт (`transcript_object`) і стан передзвону. Трохи згодом приходить `call_analyzed` з підсумком і полями Post-Call Analysis; після неї адмінам іде один звіт про дзвінок (підсумок, ключові поля, згорнутий діалог), а слідом запис розмови. Якщо `call_analyzed` не прийде за 2 хв, звіт надсилається без підсумку. Для аудіо бекенд за `call_id` читає свіжий `recording_url` через Retell API і не зберігає його.
7. Відповідь custom function — JSON `{"result": "..."}` (або `{"error": "..."}`), Retell передає її LLM агента. Webhook відповідає `204`; при збої — `500`, і Retell повторить подію (обробка ідемпотентна).

## Які дані потрапляють у заявку

Після усного підтвердження Олена передає в `submit_booking_request` ім'я, телефон, обрану послугу, місто, дату (зараз завжди «Не вказано»), побажання щодо половини дня та короткий підсумок запиту. Backend перевіряє значення й записує ці поля в `booking_requests`; Звіт для адміністраторів бере поля з цього рядка, а підсумок і діалог із даних дзвінка. Для дзвінка без заявки поля (ім'я, телефон, послуга, місто, час, скарга) беруться з Post-Call Analysis Retell. Заявка без жодної події кінця дзвінка за 15 хв надсилається окремою карткою.

## Локальний запуск

Потрібні Python 3.12+ або Docker Compose. Для найпростішої демонстрації не купуйте телефонний номер чи VPS: запустіть backend локально, а агента перевіряйте через web call у Retell Dashboard (кнопка Test). Щоб Retell дістався локального webhook, потрібен тимчасовий HTTPS tunnel або staging URL.

### Варіант A: Docker Compose

У PowerShell з кореня проєкту:

```powershell
Copy-Item .env.example .env
```

Відредагуйте `.env`: задайте `RETELL_API_KEY` (ключ із позначкою webhook у Retell Dashboard → Settings → API Keys) і простий URL-безпечний пароль `POSTGRES_PASSWORD` (лише латинські літери/цифри для локального Compose). `TG_BOT_TOKEN` та `TG_ADMIN_IDS` залиште порожніми, якщо Telegram ще не готовий. `FORWARD_RECORDINGS_TO_TELEGRAM` залиште `false`.

Запуск і перевірка:

```powershell
docker compose up --build
Invoke-RestMethod http://localhost:8000/health
```

Очікується `ok: true`; міграції запускаються під час старту. Зупиніть `Ctrl+C`. `docker compose down` зберігає локальну базу у volume; `docker compose down -v` видаляє її разом із демонстраційними даними.

### Варіант B: Python та локальний PostgreSQL

1. Встановіть і запустіть PostgreSQL локально. Через `psql -U postgres` або pgAdmin створіть окремого користувача й базу:

   ```sql
   CREATE USER booking WITH PASSWORD '<ваш_власний_пароль_з_літер_і_цифр>';
   CREATE DATABASE booking OWNER booking;
   ```

2. Скопіюйте `.env.example` у `.env` та вкажіть `DATABASE_URL=postgresql://booking:<той_самий_пароль>@localhost:5432/booking`. Для простоти локального старту візьміть пароль лише з латинських літер і цифр; інакше спеціальні символи у URI потрібно URL-кодувати.
3. З кореня репозиторію виконайте:

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
   ```

4. Перевірте `http://127.0.0.1:8000/health`.

У локальному Python запуску `.env` має містити адресу `localhost`; у Compose її задає сервіс `app` як `db:5432`. Telegram необов'язковий: якщо немає токена або chat ID, сповіщення не запускаються, заявки лишаються у БД.

## Налаштування Telegram-групи адміністраторів

1. У `@BotFather` створіть бота через `/newbot`; його токен збережіть у менеджері паролів. Якщо токен потрапив у скриншот чи чат, відкличте його через BotFather та замініть у `.env`.
2. Створіть приватну групу адміністраторів і додайте бота як учасника. Для надсилання ботом повідомлень права адміністратора зазвичай не потрібні.
3. Напишіть у групі команду `/start@<username_бота>`, щоб у Telegram з'явився update для цього бота. Якщо в боті вже налаштований Telegram webhook, `getUpdates` не працюватиме, доки той webhook не буде прибраний.
4. У корені проєкту запустіть `python scripts/get_telegram_chat_id.py`. Скрипт читає токен з локального `.env` і друкує тільки числові chat ID. Для групи ID зазвичай від'ємний і може починатися з `-100`. Не відкривайте URL із токеном у браузері й не копіюйте сирий Telegram update у чат.
5. Запишіть локально у `.env`:

   ```dotenv
   TG_BOT_TOKEN=<токен цього Telegram-бота>
   TG_ADMIN_IDS=<числовий ID приватної групи>
   ```

6. Перезапустіть застосунок. Перевірте доставку тільки після окремого demo-виклику з вигаданими даними.

Можна вказати кілька ID через кому; успіхом вважається доставка хоча б в один заданий чат. Telegram не є сховищем для аудіозаписів пацієнтів: доступ і строки видалення мають бути окремо погоджені до реального використання.

## Підключення Retell

Покрокова інструкція — у [`retell/README_RETELL.md`](retell/README_RETELL.md). Коротко: агент Retell (Single Prompt) з промтом Олени, custom function `submit_booking_request` → `https://<host>/retell/function`, end-call tool `endCall`, webhook агента → `https://<host>/retell/webhook` з подіями `call_ended` і `call_analyzed`, Post Call Extraction з полями для звіту, мова `uk-UA`.

### Пересилання записів

### Запис не надіслано

Якщо запис не вдалося надіслати (Retell ще не віддав файл, Telegram недоступний), бекенд повторює спроби з наростаючою паузою: 30 с, 1, 2, 5, 10, 20, 30 хв і далі щогодини, разом близько 4,5 год. Текстові звіти від цього не залежать. Після останньої невдалої спроби або помилки, яку повтор не виправить (файл завеликий, хост не дозволений), адміністратори отримують коротке попередження «Запис розмови не надіслано» з `call_id`. Причину видно в колонці `recording_last_error`.

Щоб надіслати конкретний запис ще раз, коли причину усунено, підставте `call_id` з попередження:

```bash
docker compose exec db psql -U booking -d booking -c "UPDATE call_logs SET recording_attempts = 0, recording_failed_at = NULL, recording_next_attempt_at = NULL WHERE call_id = 'call_...'"
```

Протягом 15 с бекенд спробує знову.

Запис не надсилається в Telegram, доки `FORWARD_RECORDINGS_TO_TELEGRAM=false`. Якщо для синтетичного демо аудіо справді потрібне, увімкніть `FORWARD_RECORDINGS_TO_TELEGRAM=true` і задайте `RETELL_RECORDING_HOSTS`.

Backend робить `GET https://api.retellai.com/v2/get-call/{call_id}` з `Authorization: Bearer <RETELL_API_KEY>`, бере звідти `recording_url` і завантажує файл без ключа. URL приймається лише для HTTPS hostname з `RETELL_RECORDING_HOSTS` (так само й redirect). Hostname подивіться у першому тестовому дзвінку в Dashboard (поле recording), не копіюючи сам URL у чат чи код. Backend обмежує файл 45 MiB і не записує URL у базу чи лог.

Цей перемикач контролює лише пересилання з backend у Telegram. Retell зберігає запис у себе відповідно до `data_storage_setting` агента. Не вмикайте запис/пересилання для реальних дзвінків без погоджених згоди, договорів, доступів і строків зберігання.

## Номер і провайдер телефонії

Для першої демонстрації директору номер не потрібен: тестуйте web call у Retell Dashboard. Номер можна купити в Retell (переважно US) або підключити свій через SIP trunk / імпорт номера (Twilio, Telnyx тощо). Для українського номера спочатку запитайте поточного оператора клініки про SIP trunk/переадресацію і письмову ціну; не купуйте номер до тесту якості з Retell.

## Рішення

- Агент збирає заявки й допомагає обрати послугу з затвердженого списку; він не оцінює стан і не замінює рішення медичного працівника. До реальних дзвінків клініка має затвердити каталог послуг і правила направлення.
- Коли людина не знає послуги, агент пропонує консультацію флеболога лише для явно згаданих питань про видимі вени, судинні зірочки, важкість або набряк ніг; консультацію проктолога — лише за прямим запитом до проктолога. Для інших або неясних запитів пропонується передзвін. Процедури й обстеження за скаргами не підбираються. Це безпечне обмеження, а клініка має затвердити каталог і мапу направлення до демонстрації.
- Поля дати, бажаної половини дня та короткого підсумку обов’язково мають бути присутні у виклику інструмента. Якщо дату чи побажання не названо, передається «Не вказано»; фактичний час адміністратор узгоджує пізніше.
- Якщо телефон відсутній, він порожній лише для `Передзвін`; в інших випадках схема просить номер. Синтаксично валідні типові українські формати нормалізуються до `+380…`.
- Сповіщення доставляються за принципом щонайменше однієї спроби. Після падіння між HTTP-відправкою й записом результату можлива повторна доставка; idempotency захищає створення заявки, але Telegram не надає транзакційної exactly-once доставки.
- Пересилання записів у Telegram вимкнене за замовчуванням. Якщо його окремо ввімкнути для демо, backend отримує recording_url через автентифікований Retell API; URL не зберігається, а його домен має бути в точному HTTPS allowlist.
- Секрети з попередніх скриншотів вважайте розкритими. Відкличте Telegram Bot token і старі ключі Vapi у відповідних кабінетах. `RETELL_API_KEY` тримайте лише в `.env`.
- Docker/Compose конфігурація — тільки локальна демонстраційна, без публічного TLS, резервного копіювання, моніторингу чи автоматичної ротації секретів.

## Не готово до реальних даних

Перед реальними дзвінками клініка й команда мають завершити та письмово погодити:

- договори з клінікою, Retell, телефонним провайдером і всіма обробниками даних;
- правову підставу та узгоджене повідомлення/згоду на запис і обробку даних;
- політику зберігання та автоматичного видалення транскриптів, заявок і записів у PostgreSQL, Retell й Telegram;
- production-хостинг, TLS, мережеві правила, резервні копії та перевірене відновлення БД;
- моніторинг помилок/черг без запису ПІБ, номерів, скарг, секретів і signed URL;
- ротацію секретів, контроль доступу до Telegram-групи та рішення, чи допустимо надсилати туди записи;
- затвердження клінікою каталогу послуг, правил рекомендації консультацій і маршруту передзвону;
- перевірку якості розпізнавання/синтезу української та погоджений сценарій передачі звернення адміністратору;
- юридичну оцінку First Message про запис і вимог до медичних/персональних даних.

## Поточні межі перевірки

У цій копії немає вихідних pytest-тестів і демо-фікстур; автоматизований тестовий набір не додавався, бо попередня вимога була прибрати тести й приклади. Міграції потребують перевірки на окремій локальній БД. Docker Compose-конфіг можна перевірити без запуску контейнерів, але працездатність локального Docker daemon із цього середовища не підтверджена. Зміни тут не підключаються до Retell, Telegram чи робочої БД автоматично.

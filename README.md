# Verika — тестовий бекенд голосового асистента

Цей репозиторій — лише технічний пілот. Усі приклади є вигаданими.

## Локальний запуск

Скопіюйте `.env.example` у `.env`, встановіть довгий випадковий `VAPI_SECRET`; `TG_BOT_TOKEN` та `TG_ADMIN_IDS` можна залишити порожніми.

**Docker:** `docker compose up --build` запускає застосунок і PostgreSQL. Docker має бути встановлений.

**Локальний PostgreSQL:** створіть базу даних і задайте `DATABASE_URL=postgresql://...` у `.env`, потім `pip install -r requirements.txt` і `uvicorn app.main:app --reload`.

Тести: `pip install -r requirements-dev.txt` і `pytest -q`. Вони не потребують мережі, Docker чи PostgreSQL; інтеграційні тести запускаються лише за наявності `TEST_DATABASE_URL`.

## Архітектура

1. `app/main.py` приймає Vapi webhook і викликає єдиний інструмент заявки.
2. `app/schemas.py` нормалізує та перевіряє дані.
3. `app/urgency.py` шукає ознаки небезпеки як другу лінію захисту поверх рішення LLM, а не заміну клінічного тріажу.
4. `app/db.py` зберігає заявки та журнали викликів.
5. `migrations/` містить послідовні SQL-міграції, включно з незміненою `003_recordings.sql`.
6. `app/notifier.py` доставляє повідомлення адміністраторам і повторює невдалі спроби.
7. `app/telegram.py` надсилає сповіщення Telegram.
8. `prompts/olena_system_prompt.md` — системний промт асистента.
9. `scripts/simulate_vapi.py` надсилає вигадані сценарії на локальний webhook.
10. `tests/` перевіряє валідацію, urgency, webhook, Telegram та форматування.

## Змінні середовища

`DATABASE_URL` — DSN PostgreSQL; `VAPI_SECRET` — секрет вебхука; `TG_BOT_TOKEN` та `TG_ADMIN_IDS` — опційні параметри Telegram. Без Telegram заяви зберігаються у БД, а сповіщення вимкнені. `APP_ENV=test` дозволяє тестовий секрет.

## Рішення

- Порожній телефон дозволено лише для невідкладної заявки або «Передзвін»; інакше потрібен номер у типових українських форматах, нормалізований до `+380XXXXXXXXX`.
- Детектор urgency зроблено з ухилом у recall: неоднозначні формулювання можуть дати хибне пріоритетне спрацювання. Це страховка поверх рішення мовної моделі, не медичний тріаж.
- Транскрипт розбирається за `User:` та `Customer:`; формат транскрипту слід звірити на реальних тестових подіях.
- `003_recordings.sql` додає поля до `call_logs`, отже її слід запускати після базової міграції `002_call_logs.sql`.
- Примітка: попередження про запис у `firstMessage` — технічний заповнювач; юридичне формулювання має узгодити юрист.

## Не готово до реальних даних

Немає угод з клінікою, Vapi чи іншими обробниками даних, процедури згоди пацієнтів, політики зберігання/видалення даних, production-хостингу, моніторингу, ротації секретів, обмеження доступу до записів у Telegram чи юридичної оцінки. Не використовуйте реальні дані до закриття цих пунктів.
